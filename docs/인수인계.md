## 3. 핵심 결정과 이유

- **도구: React 19 + three.js + Electron 45 (TypeScript, Vite 8)**. 이유: "rea"와 가장 가까운 해석이고, 3D 뷰어·화면 완성도가 높으며 자동 검증이 쉽다. 비교한 후보: Python+Qt+Open3D(알고리즘 품질은 더 좋지만 화면 제작·검증이 불리), C++/Qt(개발 기간 과다).
- **Node.js 24.22.3 LTS를 휴대용으로 설치**: `.tools\node` 폴더에만 풀었다(공식 nodejs.org zip, SHA-256 일치 확인). 시스템 PATH·레지스트리는 건드리지 않았다. 폴더를 지우면 흔적이 남지 않는다.
- **알고리즘은 직접 구현**(Artec 고유 알고리즘과 무관): 구멍 메우기(귀 자르기 + 세분·스무딩), 타우빈 스무딩, ICP(점-평면, kd-트리), PCA 거친 정렬, 퓨전(복셀 부호 거리 누적 + 마칭 큐브). 단순화만 오픈소스 meshoptimizer를 쓴다.
- **무거운 계산은 웹 워커에서 실행**해 화면이 멈추지 않게 했다. 데이터는 불변으로 다뤄 실행 취소(최대 30단계)가 가볍다.
- **보안**: 화면 쪽은 샌드박스·컨텍스트 격리. 파일 읽기·쓰기는 사용자가 대화상자로 고른 폴더에만 허용.

## 4. 구현된 것과 빠진 것

### 구현됨 (모두 자동 검증 통과)

## 7. 알려진 한계·주의

- 수동 점 정렬 없이 "정밀 정렬"만 누르면 두 스캔이 대략 겹쳐 있을 때만 맞는다. 많이 어긋나면 점 정렬을 먼저 할 것.
- "위치 무관 자동 정렬"은 두 객체의 겹침이 클 때만 믿을 만하다(부분 스캔끼리는 실패할 수 있음).
- 퓨전은 표면 근처 2복셀 범위만 채운다. 얇은 물체(두께 < 4복셀)는 앞뒤 면이 간섭할 수 있어 해상도 값을 줄여야 한다.
- 법선 없는 점군의 법선 방향은 "점군 중심에서 바깥쪽" 휴리스틱이라 오목한 형상에서는 뒤집힐 수 있다.
- 구멍 메우기는 막 형태(최소 곡면에 가까움)로 메운다. 곡률을 이어 주지는 않는다.
- 여러 객체를 한 번에 내보내면 하나로 합쳐지고 텍스처는 빠진다(정점 색만 유지).
- PowerShell 스크립트(`scripts\*.ps1`)와 `.cmd`는 **ASCII로만** 쓸 것. Windows PowerShell 5.1이 BOM 없는 UTF-8을 ANSI로 읽어 한글이 깨진다(이번 작업에서 한 번 실패한 원인).
- Electron을 스크립트로 띄울 때는 환경변수 `ELECTRON_RUN_AS_NODE`를 지워야 창 앱으로 뜬다(스크립트에 반영됨).

3. 상위 후보를 점-평면 ICP로 다듬고 엄격한 허용 오차로 다시 채점. 복도(벽이 한 방향으로만 나열)일 때는 길 방향 0.25m 간격 전수 훑기 후보를 추가(`corridorCandidates`). 점수 = 겹침 − 40×위반(겹친 정도를 곱함).
4. 쌍 점수 `MIN_PAIR_SCORE = -1.2` 이상만 이어 붙임(최대 신장 트리), 마지막에 한 스캔씩 나머지 전부에 다시 ICP.
- 시행착오(같은 증상 3번 이상): 복도에서 스캔 3·4가 1·2에 안 붙음 → 위반 가중치 조정(효과 없음) → 비스듬한 면 제외(개선) → 탐색 반경이 벽 점만으로 재서 ±13m로 좁았음(고침) → 수평 보정 → **점수 임계가 너무 엄격**(겹쳐 그린 그림은 이미 맞았음)이 마지막 원인. 숫자 점수만 믿지 말고 겹쳐 그린 그림(`render`)을 먼저 볼 것.
